# 二次仿写降重优化方案

> 调研日期：2026-08-16
> 背景：当前「二次仿写」功能使用文皮皮检测相似度为 21.29%（判定为抄袭），需要优化到 5% 以下（判定为原创）

---

## 一、查重检测算法原理（文皮皮 / 知网通用）

### 1.1 检测引擎架构

文皮皮采用「河图引擎」，基于大模型技术，检测维度包括：

| 检测层 | 算法 | 原理 | 触发阈值 |
|--------|------|------|---------|
| 字面层 | 滑动窗口 | 连续 13 个中文字符完全匹配即判定重复 | 1 处即标记 |
| 指纹层 | SimHash | 文本段生成哈希指纹，汉明距离 < 3 判为相似 | 段落级 |
| 语义层 | BERT 向量 | 句子向量余弦相似度，捕捉「换词不换意」 | cos > 0.85 |
| AI 检测层 | 困惑度 + 突发度 | 检测文本是否由 AI 生成 | 困惑度 < 阈值 |

### 1.2 相似度计算规则

- 相似度范围：-100% ~ +100%
- 越小越原创，越大越抄袭
- **< 5%**：原创
- **5% ~ 10%**：轻度抄袭（可忽略）
- **≥ 10%**：抄袭
- **≥ 30%**：严重抄袭

### 1.3 核心发现：连续 13 字是硬红线

查重系统最基础的检测单元是「连续 N 个字的完全匹配」：
- 知网：连续 13 个中文字
- 英文系统（Turnitin）：连续 8 个英文单词
- 文皮皮河图引擎：结合以上 + 语义相似度

**关键启示**：只要打断原文中任何连续 13 字的片段，字面层检测就无法命中。

## 二、当前实现的问题诊断

### 2.1 代码路径分析

当前 `rewriteArticle()` 函数（`tasks.ts:209`）的处理链路：

```
用户输入原文 → 拼 prompt → 调 LLM → 直接输出
```

**缺失环节**：
- 没有分句/分段预处理
- 没有连续词打断的硬约束
- 没有后处理（randomizer.ts 未被调用）
- dedup 意图下没有使用 humanizer-prompt

### 2.2 当前 prompt 的致命缺陷

```
你是一位专业改写编辑。请对以下文章进行中度改写（保留60%原意，调整结构和表达）。
目标：降重，让文字焕然一新，过查重检测
改写要求：
- 语义等价，不添加原文没有的事实
- 文字焕然一新，可读性高
- 符合公众号写作风格
- 直接输出改写后的文章
```

**问题清单**：

| 问题 | 影响 | 严重度 |
|------|------|--------|
| 没有连续词打断约束 | AI 保留大量原文短语和句式骨架 | 致命 |
| 「焕然一新」太模糊 | AI 无法理解具体操作方式 | 高 |
| 没有分维度改写指导 | AI 只做表面同义词替换 | 高 |
| 没有逻辑重排要求 | 论述顺序与原文高度一致 | 中 |
| 温度 0.85 无结构引导 | 高随机性但方向错误 | 中 |
| 整篇一次性处理 | 长文改写容易「偷懒」复用原文 | 中 |

### 2.3 为什么 21.29% 被判抄袭

实测分析（推断）：
1. AI 改写时保留了原文中大量「连续 8-15 字」的片段（特别是专业表述、固定搭配）
2. 虽然做了同义词替换，但句式骨架相同 → 语义层检测命中
3. 段落顺序与原文一致 → SimHash 指纹相似
4. 没有节奏打乱 → 突发度检测暴露 AI 特征

## 三、业界降重方法论（五维度模型）

通过调研论文降重工具（嘎嘎降AI、比话降AI、率零等）和 ChatGPT 降重 prompt 最佳实践，提炼出系统化的五维度降重模型：

### 维度一：句式结构变换（打破均匀性）

| 技巧 | 操作 | 示例 |
|------|------|------|
| 长句拆短 | 一个复杂句拆成 2-3 个短句 | 「随着AI技术的发展，越来越多的企业开始采用智能客服系统」→「AI技术发展很快。企业坐不住了，纷纷上智能客服。」 |
| 短句合并 | 碎片化短句合并为有节奏的长句 | 反向操作 |
| 超短句插入 | 3-8 字的断句 | 在论述中间插入「问题来了。」「没那么简单。」 |
| 主被动互换 | 主动句↔被动句 | 「公司采用了新方案」→「新方案在公司落地了」 |

**效果**：单独使用可降低相似度 10-15%

### 维度二：词汇层面替换（降低预测准确性）

| 技巧 | 操作 | 示例 |
|------|------|------|
| 低频词替换高频搭配 | 用不常见但正确的表达替换 AI 标准搭配 | 「进行了深入的分析」→「掰开揉碎看了一遍」 |
| 删除 AI 标志连接词 | 删除或替换 | 「值得注意的是」→ 直接说内容 |
| 领域缩写混用 | 全称和缩写交替使用 | 「卷积神经网络」偶尔写成「CNN」 |

**效果**：单独使用可降低相似度 8-12%

### 维度三：逻辑结构重组（改变论证模式）

| 技巧 | 操作 | 示例 |
|------|------|------|
| 倒装论述 | 先结论后原因 | 「因为X所以Y」→「Y。原因很直接——X。」 |
| 打乱段内顺序 | 不按原文的论述顺序 | 「背景→问题→方案→效果」→「效果→方案→问题→背景」 |
| 删除显性连接词 | 去掉「首先、其次、最后」 | 让段落自然衔接 |
| 插入自我修正 | 加入质疑和反思 | 「准确来说，这里用'显著'不太严谨」 |

**效果**：单独使用可降低相似度 12-18%（最强维度）

### 维度四：语气人称注入（加入个人化表达）

| 技巧 | 操作 |
|------|------|
| 主观判断词 | 「我个人觉得」「说实话」「不确定是不是个例」 |
| 带情绪过渡 | 「这就很离谱了——」「好消息是，」 |
| 承认局限 | 「这部分我了解不多」「方法上有个问题没想清楚」 |

**效果**：单独使用可降低相似度 5-10%

### 维度五：文本节奏打乱（制造不均匀感）

| 技巧 | 操作 |
|------|------|
| 段落长度大幅波动 | 一段 200 字 → 下一段 30 字 → 再 150 字 |
| 突然插入列表/表格 | 大段论述中切到简短列表 |
| 括号补充 | 「采用了五折交叉验证（老实说十折更稳，但时间不够）」 |

**效果**：单独使用可降低相似度 5-8%

### 五维度叠加效果

实测数据（来自业界报告）：
- 原文 AI 率 82% → 五维度叠加后降至 25%
- 配合专业工具可降至 5% 以下

## 四、优化方案设计

### 4.1 总体架构升级

从「单 prompt 一次性改写」升级为「分层处理管道」：

```
原文输入
  ↓
[Layer 0] 预处理：分段分句 + 提取关键词/专有名词
  ↓
[Layer 1] AI 深度改写：五维度 prompt + 连续词硬约束
  ↓
[Layer 2] 连续词检测：逐句比对原文，找出残留的连续 8+ 字片段
  ↓
[Layer 3] 局部修补：对残留片段做二次改写
  ↓
[Layer 4] 随机化后处理：调用 randomizer（同义词替换 + 节奏打散）
  ↓
[Layer 5] 质量检测：调用 pattern-detector 确认去 AI 味
  ↓
输出
```

### 4.2 核心改进：新 Prompt 设计

#### 降重意图（intent = 'dedup'）的专用 System Prompt

```markdown
你是一位专业的文章降重改写师。你的核心任务是将原文改写为一篇全新的文章，
让查重系统无法检测出与原文的关联。

## 硬约束（违反即失败）

1. **连续词打断**：改写后的文章中，不能存在与原文连续 8 个字以上完全相同的文字片段。
   每一句话都必须用全新的表达方式重写。
2. **语义等价**：保留原文的核心信息和观点，不添加原文没有的事实。
3. **关键词保留**：专有名词、人名、地名、品牌名、数字保持不变。

## 五维度改写操作（每个维度都必须执行）

### 维度一：句式重构
- 把原文的长句拆成 2-3 个短句
- 把原文的短句合并成有节奏的长句
- 主动句改被动句，被动句改主动句
- 引入 3-8 字的超短断句

### 维度二：词汇革新
- 用日常口语替换书面语（「进行分析」→「看了一遍」）
- 删除所有套话（「值得注意的是」「综上所述」）
- 同一个概念用不同的表达方式（第一次出现用全称，后面用简称/代词）

### 维度三：逻辑重排
- 打乱原文的论述顺序（不要按原文的段落顺序来）
- 先说结论再补原因（原文如果是先因后果，改成先果后因）
- 删除「首先、其次、最后」等显性连接词，用自然过渡替代

### 维度四：人格注入
- 加入第一人称视角（「我发现」「说实话」「有意思的是」）
- 偶尔表达主观感受（「这个数据挺意外的」）
- 适当加入反问或感叹

### 维度五：节奏打乱
- 段落长短交替：一段长（150-200字）→ 下一段短（30-50字）
- 偶尔用一句话成段
- 在合适的地方使用列表替代连续论述

## 检验标准

改写完成后，逐句检查：
- 是否存在与原文连续 8 字以上相同的片段？→ 如果有，重写那句
- 是否只做了同义词替换而保留了原文句式骨架？→ 如果是，重构句式
- 段落顺序是否与原文一致？→ 如果是，重新排列

直接输出改写后的文章，不要任何解释。
```

### 4.3 分段处理策略

当原文超过 2000 字时，不再一次性改写，而是：

1. 将原文按段落拆分
2. 每段独立改写（带上下文摘要保持连贯）
3. 最后拼接并做全文通顺性调整

这样避免 LLM 处理长文时「偷懒」保留原文片段的问题。

### 4.4 连续词检测后处理（新增 Layer 2）

在 AI 改写完成后，用代码层面检测残留的连续词：

```typescript
/**
 * 检测改写文本中是否残留与原文连续 N 字以上相同的片段
 * 返回所有命中片段的位置和内容
 */
function detectConsecutiveMatches(original: string, rewritten: string, threshold = 8): Match[] {
  const matches: Match[] = []
  for (let len = threshold; len <= 20; len++) {
    for (let i = 0; i <= original.length - len; i++) {
      const fragment = original.slice(i, i + len)
      const pos = rewritten.indexOf(fragment)
      if (pos !== -1) {
        matches.push({ fragment, originalPos: i, rewrittenPos: pos, length: len })
      }
    }
  }
  // 去重：保留最长匹配
  return deduplicateMatches(matches)
}
```

对于检测到的残留片段，可以：
- 自动调用 LLM 对这些片段做二次改写
- 或使用同义词替换 + 句式变换做规则化处理

### 4.5 整合 randomizer 后处理

当前 `rewriteArticle` 没有调用 `randomizer.ts`，应该在 dedup 意图下启用：

```typescript
// 在 streamWithFallback 返回结果后，追加后处理
if (req.intent === 'dedup') {
  const processed = randomizeText(fullText, {
    synonyms: true,
    punctuation: true,
    paragraphRhythm: true,
    pauseWords: true,
  })
  // 输出 processed 替代原始 fullText
}
```

## 五、更高维度的思考：从「降重工具」到「内容重生平台」

### 5.1 思维升维：不是「改」，是「重生」

当前的思路停留在「如何改原文使其过检测」，这是一个防守性思维。

更高维度的思考是：**将原文视为「信息源」，生成一篇独立的新文章**。

区别在于：
- **改写思维**：原文是「骨架」，改写是给骨架换衣服 → 骨架还在，容易被检测
- **重生思维**：原文是「素材」，用自己的方式重新讲这个故事 → 全新骨架，检测无从对比

### 5.2 三级改写模型

| 级别 | 思路 | 与原文的关系 | 过检概率 |
|------|------|-------------|---------|
| L1 同义替换 | 换词 | 骨架 100% 相同 | 低（20%+相似度） |
| L2 句式重构 | 换句式 + 换顺序 | 骨架 50% 相同 | 中（8-15%相似度） |
| L3 信息重组 | 提取要点 → 重新组织叙事 | 骨架完全不同 | 高（< 5%相似度） |

**当前我们停留在 L1-L2 之间，需要跨越到 L3。**

### 5.3 L3「信息重组」的实现思路

```
原文
  ↓ Step 1: 信息抽取
提取核心要点（5-10 个 bullet points）
  ↓ Step 2: 叙事重构
选择全新的叙事结构（时间线 / 问题驱动 / 对比式 / 故事式）
  ↓ Step 3: 自由写作
基于要点 + 新结构，生成全新文章
  ↓ Step 4: 质检
连续词检测 + AI 模式检测
```

对应的 prompt 策略：

**Step 1（信息抽取 prompt）**：
```
请阅读以下文章，提取其中所有核心信息点，以bullet point形式列出。
不要保留原文的任何措辞，只提取纯粹的事实和观点。
```

**Step 2+3（重构写作 prompt）**：
```
基于以下信息点，用你自己的方式写一篇全新的文章。
要求：
- 选择一个与原文不同的叙事结构
- 完全用自己的话表达
- 不要参考任何已有文章的措辞
- 字数约 XXX 字
```

### 5.4 多模态对抗策略

除了文本层面的改写，还可以引入：

1. **视角转换**：原文第三人称 → 改为第一人称经历
2. **文体转换**：原文议论文 → 改为叙事文/对话体/问答体
3. **受众转换**：原文面向专业人士 → 改为面向小白的科普
4. **媒介转换**：原文公众号长文 → 改为短视频文案/播客脚本

这些转换天然地会产生完全不同的文本结构，从根本上避免相似度检测。

### 5.5 举一反三：可落地的产品功能扩展

| 功能 | 描述 | 实现复杂度 |
|------|------|-----------|
| 智能降重模式 | 自动选择最佳改写策略 | 中 |
| 逐句对比预览 | 改写后逐句显示与原文的对照 | 低 |
| 相似度预估 | 改写前预估可能的相似度 | 中 |
| 分段独立改写 | 长文拆分+分段改写+拼接 | 低 |
| 残留词高亮 | 标记改写后仍与原文相同的片段 | 低 |
| 二次修补 | 对高亮片段自动二次改写 | 中 |
| 多版本对比 | 生成 3 个不同版本供用户选择 | 中 |
| 文体切换降重 | 一键切换叙事视角/文体 | 高 |

## 八、总结

### 根因

当前仿写效果不佳的根本原因不是 AI 模型能力不足，而是 **prompt 工程太简单 + 处理管道太短**。

### 核心洞见

1. 查重系统有明确的算法规则（连续 13 字），我们可以针对性地对抗
2. 降重不是「换词」，而是「换骨架」—— 从 L1 同义替换升级到 L3 信息重组
3. 五维度方法论（句式/词汇/逻辑/语气/节奏）需要全部覆盖，缺一效果打折
4. 分层处理管道（AI改写 → 连续词检测 → 局部修补 → 随机化）比单次 prompt 稳定得多
5. 最高维度的解法是「重生」而非「改写」—— 把原文当素材而非骨架

### 预期效果

- Phase 1 完成后：相似度 21% → 8% 以下
- Phase 2 完成后：相似度稳定 < 5%，长文支持
- Phase 3 完成后：相似度 < 3%，且文章质量超越原文
