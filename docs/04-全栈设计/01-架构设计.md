## 3. 数据库设计（MySQL）

### 3.1 users — 用户表
```sql
id, username, email, password_hash, avatar_url,
is_activated, card_key, plan(free/pro), 
model_config(JSON), created_at, updated_at
```

### 3.2 card_keys — 卡密表
```sql
id, code, is_used, used_by, used_at, 
plan, duration_days, created_at
```

### 3.3 style_prompts — 风格库
```sql
id, user_id, name, description, 
source_urls(JSON), prompt_content, 
created_at, updated_at
```

### 3.4 creations — 创作历史
```sql
id, user_id, type(title/article/rewrite/platform/deai),
title, content(LONGTEXT), meta(JSON),
source_style_id, platform, ai_score,
created_at, updated_at
```

### 3.5 knowledge_docs — 知识库文档
```sql
id, user_id, filename, file_path, file_size,
content_text(LONGTEXT), keywords(JSON),
chunk_count, created_at
```

### 3.6 trending_cache — 热点缓存（Redis辅助）
```sql
id, platform, title, url, heat_value, 
category, rank, fetched_at
```

## 4. API 设计

### Auth
- POST /api/auth/register
- POST /api/auth/login
- POST /api/auth/activate  (卡密激活)
- GET  /api/auth/me

### AI 功能
- POST /api/ai/title          (爆款标题)
- POST /api/ai/style-analyze  (风格分析)
- POST /api/ai/generate       (定向生成，SSE流式)
- POST /api/ai/rewrite        (二次仿写)
- POST /api/ai/platform       (多平台推文)
- POST /api/ai/deai           (去AI味，SSE流式)
- POST /api/ai/detect         (内容检测)

### 热点
- GET /api/trending?platform=weibo|zhihu|douyin|toutiao&category=all

### 知识库
- POST /api/knowledge/upload
- GET  /api/knowledge/list
- DELETE /api/knowledge/:id
- POST /api/knowledge/search

### 风格库
- POST /api/style/create
- GET  /api/style/list
- DELETE /api/style/:id

### 创作历史
- GET  /api/creations?page=1&type=all
- GET  /api/creations/:id
- DELETE /api/creations/:id
- PATCH /api/creations/:id  (更新内容)

### 模型设置
- GET  /api/settings/models
- PUT  /api/settings/models  (保存加密Key)
- POST /api/settings/test    (测试连通性)

## 5. AI 代理设计

### 支持模型

|-------|------|---------|
| DeepSeek | deepseek-chat | api.deepseek.com |
| OpenAI | gpt-4o-mini | api.openai.com |

| 智谱 | glm-4-flash | open.bigmodel.cn |
| Gemini | gemini-1.5-flash | generativelanguage.googleapis.com |

### 故障切换逻辑
1. 按用户配置的优先级顺序尝试
2. 某个 Key 返回 429/500 时自动切换下一个
3. 所有都失败时返回明确错误

### Key 加密
- 前端传来的 Key 用 AES-256-GCM 加密存 MySQL
- 使用时解密，不在响应中返回明文

## 6. 安全设计

- JWT 有效期 7d，refresh token 30d
- bcrypt rounds=12 hash 密码
- Rate limit: 登录 5次/分钟，AI接口 60次/小时
- CORS 白名单
- Helmet.js 安全头
- SQL 全用 prepared statements（mysql2）
- 文件上传：类型白名单 + 大小限制 20MB
