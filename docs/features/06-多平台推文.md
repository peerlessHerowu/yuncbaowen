# 多平台推文（Platform）· 功能打磨设计文档

---

## 一、现状分析

### 1.1 当前实现

- 接收原始文章 + 选择目标平台列表
- 支持 URL 自动抓取（已实现）
- 返回各平台专属文案
- JSON 解析兜底逻辑（AI 返回不合法 JSON 时有备用解析）

### 1.2 问题清单

**P0 — 核心功能**
1. 只返回文字，没有针对各平台的格式化处理
   - 小红书需要 emoji、话题标签 `#xxx`，但现在 AI 生成的格式不稳定
   - 微博需要截断到 140 字以内，但没有强制校验
   - 知乎需要结构化（有标题层级），但 AI 返回的是纯文字
2. 生成的文案不能编辑（只能复制全文，不能局部修改）
3. 没有字数显示（小红书 500 字、微博 140 字，用户不知道有没有超）

**P1 — 体验**
1. 所有平台同时生成，总耗时 30-60 秒，用户等待焦虑
2. 结果只能复制，没有「一键发布」或「跳转到平台」
3. 没有保存草稿功能
4. 格式化后无法直接预览各平台效果

**P2 — 质量**
1. 各平台文案质量参差不齐，没有质量评估
2. emoji 使用过于随机，有时过多有时没有
3. 话题标签（hashtag）没有智能推荐，全靠 AI 随机生成

## 二、竞品分析

| 工具 | 核心做法 | 值得借鉴 |
|------|---------|---------|
| Buffer | 针对每个平台有字数限制和格式预览 | 实时字数 + 超限警告 |
| Hootsuite | 平台专属编辑器 | 所见即所得的平台预览 |
| 新榜 | 一键分发 + 效果追踪 | 分发结果统计 |

**用户痛点（真实反馈）：**
- 「生成的小红书文案没有 emoji，发出去看起来很单调」
- 「微博超过 140 字了，还要自己去截断」
- 「生成完了还要去各平台手动排版，很麻烦」

## 三、优化方案

### 3.1 平台专属后处理

生成文案后，后端对每个平台做格式化处理：

```typescript
// 微博专项
function formatForWeibo(text: string): string {
  // 1. 强制截断到 140 字
  // 2. 确保有 2-3 个话题标签
  // 3. 结尾加行动召唤（「转发给需要的朋友」）
  let formatted = text.slice(0, 135)  // 留 5 字给话题
  if (!formatted.includes('#')) {
    formatted += ' #热点话题'
  }
  return formatted
}

// 小红书专项
function formatForXiaoHongShu(text: string): string {
  // 1. 确保有 emoji（每段至少 1 个）
  // 2. 结尾有 3-5 个话题标签
  // 3. 分段短（每段 2-3 句）
  // 4. 有「姐妹们」「宝子们」等互动用词
  ...
}

// 知乎专项
function formatForZhihu(text: string): string {
  // 1. 有明确的标题层级
  // 2. 有数据/案例支撑
  // 3. 专业但不失亲和
  ...
}
```

### 3.2 实时流式生成（逐平台显示）

**现在：** 等所有平台都生成完才显示

**优化：** 逐平台流式生成，生成一个显示一个：
```
正在生成...
✅ 微博 (0.8s)   → 立刻显示
✅ 小红书 (1.2s)  → 立刻显示
⏳ 知乎...
⏳ 公众号...
```

后端改为 SSE 流式，每生成一个平台就推送一条事件。

### 3.3 内联编辑器

**现在：** 只能复制，不能编辑

**优化：** 每个平台文案卡片支持点击编辑：
```
┌───────────────────────────────────────────┐
│  🔴 微博    77字 ✅    [编辑] [复制] [发布] │
│                                            │
│  AI时代，会用工具的人效率是普通人的3-5倍！ │  ← 可以直接点击编辑
│  写作、设计、编程全都能用AI加速 💪          │
│  不想被时代甩下，赶紧学起来！              │
│  #AI工具 #效率提升 #职场                  │
└───────────────────────────────────────────┘
```

### 3.4 平台预览

每个平台的文案卡片做成对应平台风格的预览：
- 微博：仿微博卡片（头像 + 内容 + 底部操作栏）
- 小红书：仿小红书笔记卡片（配图占位 + 文案 + 话题标签）
- 朋友圈：仿微信朋友圈卡片样式

### 3.5 智能话题标签推荐

结合热点追踪数据，推荐与文章内容相关的热门话题标签：
```typescript
// 新增接口 POST /api/trending/hashtags
// 输入：文章内容 + 目标平台
// 输出：推荐话题标签列表（带热度）
```

## 五、UI 设计规范

### 平台颜色
- 微博：`#E6162D`
- 小红书：`#FF2442`
- 知乎：`#0066FF`
- 公众号：`#07C160`
- 抖音：`#000000` + 渐变
- 朋友圈：`#07C160`
- 视频号：`#07C160`

### 字数状态
- 正常：`text-slate-400`
- 接近上限（>80%）：`text-yellow-400`
- 超限：`text-red-400` + 振动动画

### 卡片状态
- 生成中：骨架屏（Skeleton）动画
- 已生成：渐入动画（`animate-fade-in`）
- 编辑中：边框高亮 `border-indigo-500`
