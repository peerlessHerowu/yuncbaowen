## 一、现状分析

### 1.1 当前实现

**三层流水线架构（已实现）：**
```
Layer 1: 规则引擎检测（本地，0 token）
  ↓ 评分 < 80
Layer 2: AI 定向改写（kiro-gateway）
  ↓ 质量校验（拒绝分数下降的改写）
Layer 3: 随机化处理（本地，防平台风控）
  ├── 同义词替换
  ├── 标点随机化
  ├── 段落节奏打散
  └── 口语停顿词插入
```

**规则引擎检测维度（已实现）：**
- 模式7：AI 高频词（蓬勃发展、日新月异等）
- 模式10：三元并列
- 模式14：Em Dash
- 模式22：讨好语气
- 模式27：权威感套语
- 模式28：预告式开场白
- 模式29：中文 AI 结构套路（首先/其次/综上所述）
- 模式30：句子长度均匀度（统计）
- 模式31：段落长度均匀度（统计）
- 模式32：句尾标点单一（统计）

### 1.2 现存问题（代码审计）

**问题 1：规则引擎评分缺陷**
- `PASS_SCORE = 80` 是固定值，未根据文本长度动态调整
- 短文本（<100字）命中少，分数虚高；长文本（>2000字）命中多，可能过度惩罚

**问题 2：Humanizer Prompt 缺失关键指令**
- 没有「保持原文事实不变」的强约束
- 没有「目标读者画像」指导
- 没有「改写强度」的 temperature 策略

**问题 3：Layer 3 随机化有盲区**
- 同义词替换表只有 30 个词对，覆盖率低
- 口语停顿词只在段落开头插入，缺少句中插入
- 没有处理「过度使用问号」的反向平衡

**问题 4：前端 UX 体验差**
- 改写过程无进度反馈（用户不知道在哪一层）
- 没有对比视图（原文 vs 改写后）
- 轮次数选 1 时仍然会触发 AI（之前的 bug，虽已修复但前端标签仍显示「1轮」而实际做了 AI 改写）
- 最终评分没有可视化（只显示分数数字）

**问题 5：检测维度缺失**
- 未检测「被动语态」（AI 常用）
- 未检测「信息密度」（AI 文章空洞）
- 未检测「引用标志」（AI 喜欢「研究表明」「数据显示」）

## 二、竞品分析

### 2.1 国际竞品

| 工具 | 核心技术 | 优势 | 劣势 |
|------|---------|------|------|
| Undetectable AI | 多模型集成，针对 GPTZero/Originality 优化 | 绕过率 82-94% | 英文为主，中文支持差 |
| HIX Bypass | 意义保留 + 风格变换 | 内容不失真 | 速度慢，付费贵 |
| Humanize AI | 统计特征攻击 | 针对性强 | 语义有时走形 |

**关键洞察（来源：Medium 2026年测评）：**
- 2026 年检测器已能识别「被人工处理过的 AI 内容」
- 最有效的方法是：**保留原意 + 注入作者个人声音 + 打散统计特征**
- 单纯词替换的效果越来越差，需要「深度语义重构」

### 2.2 中文竞品

| 工具 | 特点 | 缺陷 |
|------|------|------|
| 秘塔写作 | AI 改写 + 人工润色指导 | 没有评分系统 |
| 笔灵 AI | 多维度检测 | 改写效果一般 |
| AIWriteX | 过朱雀检测 | 只针对特定平台 |

**中文特有问题（未被竞品充分解决的）：**
1. 「数字+单位」组合（「5G时代」「3亿用户」）AI 写作特征很强
2. 「排比三段式」结构是中文 AI 最显著特征
3. 「之所以…是因为…」「正是由于…才…」强因果句式
4. 「不仅…还…而且…」层进式套路

## 三、优化方案

### 3.1 规则引擎扩展（新增检测模式）

**新增模式 33：被动语态**
```typescript
// AI 喜欢被动语态，真人多用主动
const PASSIVE_PATTERNS = [
  /被认为是/, /被广泛应用/, /被大量使用/, /被证明/, /被视为/,
  /得到了广泛/, /受到了关注/, /引起了重视/,
]
```

**新增模式 34：数据虚引用**
```typescript
const FAKE_DATA_PATTERNS = [
  /研究表明/, /数据显示/, /据统计/, /调查发现/, /专家指出/,
  /报告显示/, /分析认为/,
  // 注意：若后跟具体数字则降为 low（可能是真实引用）
]
```

**新增模式 35：强因果套式**
```typescript
const CAUSAL_PATTERNS = [
  /之所以.*是因为/, /正是由于.*才/, /不仅.*还.*而且/,
  /一方面.*另一方面/, /既.*又.*还/,
]
```

**新增模式 36：空洞升华句**
```typescript
const HOLLOW_ENDINGS = [
  /让我们共同.*美好未来/, /携手.*共创/, /为.*贡献力量/,
  /期待.*未来/, /相信.*一定会/, /必将.*迎来/,
]
```

### 3.2 动态评分阈值

```typescript
function calcPassScore(textLength: number): number {
  // 短文本宽松（词汇少，命中概率低），长文本严格
  if (textLength < 200) return 75
  if (textLength < 500) return 78
  if (textLength < 1000) return 80
  return 82  // 长文本要求更高
}
```

### 3.3 Humanizer Prompt 重写

```
系统：你是一个专业的中文内容编辑，负责让 AI 写的文章读起来像真人写的。

改写时必须遵守的约束：
1. 所有事实、数字、专有名词必须保持不变
2. 文章总长度变化不超过 ±20%
3. 目标读者：微信公众号用户（25-40岁，有一定文化水平，时间有限）
4. 改写后的文章应该像：一个有3年经验的内容运营在周末下午随手写的

具体改写指令（按优先级）：
1. 删除所有「首先/其次/再次/最后」编号式结构
2. 删除「综上所述/总的来说/总而言之」式总结
3. 将「在当今这个X时代」式开头改为直接切入主题
4. 将被动语态改为主动语态
5. 将「A、B 和 C」三元并列拆成两句话
6. 将抽象词（蓬勃发展/深刻影响/至关重要）改为具体描述
7. 在适当位置加入第一人称视角（「我觉得」「我发现」「说实话」）
8. 至少有一句话以问句结尾（引发读者思考）
9. 段落之间的衔接要自然，不要用「与此同时」「另外值得注意的是」

直接输出改写后的文章，不要任何前言或解释。
```

## 五、UI 设计规范

### 颜色语义
- 评分 ≥ 80：绿色 `#10B981`（通过）
- 评分 60-79：橙色 `#F59E0B`（需优化）
- 评分 < 60：红色 `#EF4444`（AI味重）

### 动画
- 改写进行中：脉冲动画 + 逐字打印效果
- 评分变化：数字滚动动画（从旧分到新分）
- 高亮词汇：渐入效果，不要突兀

### 布局
- 桌面端：左右双栏对比（各 50%）
- 移动端：上下切换 Tab（原文 / 改写后）
