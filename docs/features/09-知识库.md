# 知识库（Knowledge）· 功能打磨设计文档

---

## 一、现状分析

### 1.1 当前实现

- 支持上传 TXT/MD/JSON/PDF 文件
- 文件上传后提取文本、分块、提取关键词
- 在「定向生成」时可以关联知识库文档
- 后端基于 TF-IDF 做关键词检索（简单 BM25 近似）

### 1.2 问题

**P0**
1. PDF 提取质量差（用 `latin1` 解码提取可见文字，很多 PDF 提取出来是乱码）
2. 知识库和生成的关联性不清晰（用了知识库，但不知道是否真的用进去了）
3. 没有「查看文件内容」功能（只有文件名，看不到提取的文本）
4. 上传文件后，关键词提取结果不展示（用户不知道提取了什么）

**P1**
1. 文件大小限制 20MB，没有明确告知
2. 上传成功后没有显示「已提取 X 个 chunk，X 个关键词」
3. 删除文件没有确认弹窗
4. 没有「搜索」功能（知识库文件多了以后找不到）

**P2**
1. 不支持直接粘贴文本（只能上传文件）
2. 不支持从 URL 导入（给个链接，自动抓取内容进知识库）

## 二、优化方案

### 2.1 PDF 提取改进

当前用 regex 从 PDF 二进制提取文字，效果很差。
改为使用 `pdf-parse`（已有 npm 包，轻量），或者提示用户先转 TXT。

**备选方案：** 调用 AI（图片 OCR 方式）处理扫描版 PDF，但这会消耗 token，权衡后先用 pdf-parse。

### 2.2 直接粘贴文本

新增「粘贴文本」入口，不强求上传文件：
```
┌────────────────────────────────────┐
│  添加知识                          │
│  [上传文件] [粘贴文本] [从URL导入] │
└────────────────────────────────────┘
```

### 2.3 知识库卡片重设计

```
┌─────────────────────────────────────────────────────┐
│  📄 AI写作技巧.txt              3.2KB · 5天前上传   │
│                                                     │
│  提取：1,234 字 · 8 个 chunk · 15 个关键词          │
│  关键词：[AI写作] [效率] [工具] [提示词] ...         │
│                                                     │
│  [查看内容] [在生成中使用] [删除]                    │
└─────────────────────────────────────────────────────┘
```

### 2.4 URL 导入（复用已有 crawler）

后端已有 `fetchArticle()` 功能，直接复用：
```typescript
// POST /api/knowledge/import-url
// 输入：URL
// 输出：创建一个 knowledge_doc 记录
async function importFromUrl(userId: number, url: string) {
  const article = await fetchArticle(url)
  // 存储，复用上传文件的后续流程
  ...
}
```

## 四、UI 设计规范
