# 二次仿写（Rewrite）· 功能打磨设计文档

---

## 一、现状分析

### 1.1 当前实现

- 输入：原文（支持 URL 自动抓取） + 改写强度（轻度/中度/深度）
- 输出：SSE 流式
- 三档强度：轻度（保留70%）、中度（保留50%）、深度（仅保留核心主题）

### 1.2 问题

**P0**
1. 同定向生成一样，**流式效果没有实现打字机动画**
2. 没有「改写前后对比」视图
3. 没有改写质量评估（只是重写了，但不知道重写得好不好）
4. 没有「保留关键词」功能（改写时有些词/短语必须保留原样）

**P1**
1. 三档强度没有直观说明（用户不知道「保留50%」意味着什么变化）
2. 没有「改写目标」选择（降重 / 风格转换 / 平台适配）
3. 没有多版本对比（可以生成 3 个版本，用户选最好的）

**P2**
1. 没有「改写风格」选择（口语化 / 专业化 / 有趣化）
2. 无法指定改写参考（「按照XXX的风格改写」）

## 二、优化方案

### 2.1 改写意图选择

```
┌─────────────────────────────────────────────────────────────┐
│  我想...                                                     │
│                                                             │
│  [降重避重]   [换平台风格]   [变口语化]   [增加趣味性]      │
│  防查重/原创  公众号→小红书  书面→口语    严肃→轻松         │
│                                                             │
│  ← 选择后，下方的「改写强度」和 prompt 会自动调整 →         │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 保留关键词

```
指定必须保留的词/句（用逗号分隔）：
┌──────────────────────────────────────────┐
│ 公司名、产品名、专业术语...               │
└──────────────────────────────────────────┘
```

后端在 prompt 里注入：「以下词汇/短语必须在改写后保留原样：[keywords]」

### 2.3 多版本生成

一次生成 3 个版本，用户选最合适的：
- 后端并发请求 3 次，温度值略有差异（0.7 / 0.85 / 1.0）
- 前端展示 3 列，可以左右滑动比较

### 2.4 改写对比视图

结果展示为原文和改写后的对比，高亮改动位置（类似 Git diff）：
- 红色删除线：原文中被删/改的部分
- 绿色背景：新增的内容

## 四、UI 设计规范

```
轻度  ████████░░  保留80%原文
中度  ██████░░░░  保留60%原文
深度  ████░░░░░░  保留40%，完全重构
```
