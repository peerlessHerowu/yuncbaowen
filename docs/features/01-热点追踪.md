# 热点追踪（Trending）· 功能打磨设计文档

---

## 一、现状分析

### 1.1 当前实现

**后端：** `services/trending/fetcher.ts`
- 抓取微博热搜、知乎热榜、百度热搜、头条热榜
- 内存缓存（`Map<string, CacheEntry>`），TTL 30 分钟
- 串行抓取，失败单平台不影响其他

**前端：** `TrendingPage.tsx`
- Tab 切换不同平台
- 卡片列表展示（排名 + 标题 + 热度值）
- 「一键选题」按钮（跳转到标题生成）

### 1.2 问题清单

**P0 — 数据稳定性**
1. 抓取逻辑依赖 HTML 结构，平台改版必然导致抓取失败
2. 失败时只显示「加载失败」，没有缓存降级（即使有旧数据也不显示）
3. 没有数据新鲜度显示（用户不知道这是 30 分钟前的数据还是刚抓的）

**P1 — 功能缺失**
1. 没有「热点趋势」（不知道一个热点是上升还是下降）
2. 没有「搜索」（100 条里找不到自己关注的类目）
3. 没有「收藏」热点（看到好选题没法保存）
4. 「一键选题」只是跳转，没有把热点标题带过去
5. 没有热点分类（科技/娱乐/财经等）

**P2 — UI 问题**
1. 热度数值没有可视化（只显示原始数字，不知道 100 万和 1000 万的差距）
2. 各平台 tab 切换需要每次重新请求（没有前端缓存）
3. 卡片信息密度低，一屏看不到多少条

## 二、优化方案

### 2.1 数据稳定性

**缓存策略升级：**
```typescript
interface TrendingCache {
  data: TrendingItem[]
  fetchedAt: number
  isStale: boolean  // 超过 TTL 但仍然可用
  fetchError?: string
}

// 读取策略：
// 1. 新鲜数据（< 30min）→ 直接返回
// 2. 过期数据（30-120min）→ 返回 + 标记 stale + 后台刷新
// 3. 超旧数据（> 120min）→ 强制刷新
// 4. 无数据 + 抓取失败 → 返回错误
```

**前端数据新鲜度显示：**
```
🔴 微博热搜 · 刚刚更新        ← < 5min
🟡 知乎热榜 · 18分钟前更新    ← 5-30min
⚪ 百度热搜 · 42分钟前（已过期，刷新中...）← > 30min
```

### 2.2 热点卡片重设计

**现在：**
```
#1  某某热点标题                    1234567
```

**优化后：**
```
┌──────────────────────────────────────────────────────┐
│  #1  🔥+12%    某某热点标题                           │
│                                                       │
│  [娱乐] [明星]   ████████░░  1234万                   │
│                  热度趋势 ↑                           │
│                                                       │
│  [以此选题] [分析热点] [收藏]                         │
└──────────────────────────────────────────────────────┘
```

### 2.3 「以此选题」流程优化

现在只是跳转到标题生成页，没有携带热点信息。

**优化：**
```
点击「以此选题」
  → 标题生成页
  → topic 输入框预填「XXX 热点话题」
  → 同时显示：「基于此热点」标签
  → 生成的标题与热点相关性更高
```

### 2.4 热点聚合分析（新功能）

当用户点开一个热点，显示：
```
热点：xxx事件

📊 多平台热度
  微博  ████████  1234万
  知乎  ██████    890万
  百度  ████████  1456万

🕐 今日热度曲线（伪造，用相对趋势）
  ↗ 上午8点开始上涨
  ↘ 下午3点开始回落

💡 AI 分析角度（3个切入点）
  1. 从用户立场分析：...
  2. 从行业影响分析：...
  3. 从反常识角度：...

[以角度1生成文章] [以角度2生成文章] [以角度3生成文章]
```

## 三、实现计划

### Task 1：缓存降级策略（后端）

**文件：** `packages/backend/src/services/trending/fetcher.ts`

- [ ] 在 CacheEntry 中增加 `fetchedAt`、`isStale` 字段
- [ ] 过期后返回 stale 数据 + 触发后台刷新
- [ ] 返回数据中包含 `fetchedAt` 供前端显示

### Task 2：热点卡片 + 一键选题（前端）

**文件：** `packages/frontend/src/pages/features/TrendingPage.tsx`

- [ ] 卡片增加热度进度条（相对最高值）
- [ ] 「以此选题」携带标题跳转到 TitlePage
- [ ] 新鲜度显示（多少分钟前）
- [ ] 收藏按钮（localStorage 存储，不需要后端）
- [ ] 平台数据前端缓存（切换 tab 不重复请求）

### Task 3：热点分析侧边栏（前端 + 后端）

**后端：** 新增 `POST /api/trending/analyze`
```typescript
// 输入：热点标题
// 输出：3 个写作角度（AI 生成）
```

**前端：** 点击热点标题展开侧边抽屉
- 多平台热度对比
- AI 分析角度
- 快捷跳转到生成

## 四、UI 设计规范

### 热度颜色
- Top 3：`#FF4757`（火红）+ 火焰 emoji
- Top 10：`#FF6B81`（红粉）
- Top 10+：`#A0AEC0`（灰色）

### 趋势标志
- 上涨：`↑ +12%`，绿色
- 平稳：`→`，灰色
- 下降：`↓ -8%`，红色

### 卡片布局
- 列表视图（默认）：紧凑，一屏 8-10 条
- 卡片视图（切换）：宽松，一屏 4-6 条，更多信息
