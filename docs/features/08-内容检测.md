# 内容检测（Detect）· 功能打磨设计文档

---

## 一、现状分析

### 1.1 当前实现

四维检测，全部依赖 AI 完成：
- `ai_taste`：AI 痕迹（0-100，100=像真人）
- `forbidden_words`：违禁词（0-100，100=合规）
- `originality`：原创度（0-100）
- `readability`：可读性（0-100）

有 try/catch 兜底（AI 返回非 JSON 时，用规则引擎分数代替 ai_taste，其他维度给固定分）

### 1.2 问题清单

**P0 — 检测质量**
1. `ai_taste` 完全依赖 AI 判断 AI，这是个悖论。用同一个 Claude 判断 Claude 生成的内容，检测灵敏度存疑
2. `originality` 原创度没有任何参考依据，AI 是在凭空给分
3. `forbidden_words` 违禁词表没有实际词库，AI 自由发挥
4. 检测结果的 `issues` 数组里的 `start/end` 位置信息不准确（AI 经常返回错误的位置索引）

**P1 — 前端展示**
1. 问题高亮：有 `issues[].text` 但前端没有在原文里高亮显示
2. 综合评分只有数字，没有解释「为什么这个分」
3. 没有分项评分的解释文字
4. 没有「改进建议」的操作入口（检测完了不知道怎么改）

**P2 — 架构**
1. `ai_taste` 用 AI 检测效果不稳定，应该主要用规则引擎
2. 单次检测耗时 15-30 秒，用户体验差
3. 同一篇文章多次检测结果不一致（AI 非确定性）

## 二、重新设计方案

### 2.1 混合检测架构

```
输入文本
    ↓
┌───────────────────────────────────┐
│ 本地规则引擎（0 token，< 100ms）   │
│ - ai_taste：规则引擎评分（确定性） │
│ - 句式均匀度                      │
│ - 段落节奏                        │
│ - 标点分布                        │
│ - AI 词汇命中                     │
└───────────────────────────────────┘
    ↓ （同时）
┌───────────────────────────────────┐
│ AI 补充检测（只做规则引擎做不到的）│
│ - forbidden_words（语义级）       │
│ - readability（可读性体验）       │
│ - 逻辑连贯性                      │
└───────────────────────────────────┘
    ↓
合并结果 → 返回
```

**好处：**
- `ai_taste` 用规则引擎：快（<100ms）、稳定、确定性、可解释
- AI 只做语义级检测：减少 token 消耗，提升速度

### 2.2 违禁词本地化

把违禁词检测完全移到本地，不依赖 AI：

```typescript
// 三级违禁词
const FORBIDDEN_WORDS = {
  // 高风险（直接违规）
  HIGH: ['黄赌毒', '政治敏感词', /* ... */],
  // 中风险（平台违规，各平台不同）
  MEDIUM: {
    weixin: ['集资', '有毒', '虚假', /* ... */],
    xiaohongshu: ['效果', '最好', '第一', /* ... */],  // 广告法违禁
  },
  // 低风险（需要注意）
  LOW: ['所有', '绝对', '百分百', /* ... */],
}
```

**覆盖广告法违禁词：**
根据中国广告法，需要覆盖「最」字头词汇（最好、最快、最便宜）、「极」字头（极致、极限）、虚假功效描述等。

### 2.3 原创度改为相似度检测

原创度用 AI 凭空打分没有意义，改为：
1. **内部去重**：检测是否与用户自己的历史创作高度相似（本地 TF-IDF）
2. **结构相似度**：检测文章结构是否是套模板（段落数量、长度分布）

### 2.4 前端重设计

**检测结果卡片设计：**
```
┌─────────────────────────────────────────────────┐
│  综合评分                                         │
│  ╭────────────╮                                  │
│  │    78分     │  ← 环形进度图                   │
│  │  ⚠️ 需优化  │                                  │
│  ╰────────────╯                                  │
│                                                   │
│  分项评分                                         │
│  AI痕迹    ████████░░  82  ✅                    │
│  违禁词    █████████░  90  ✅                    │
│  原创度    ██████░░░░  60  ⚠️                    │
│  可读性    ███████░░░  70  ⚠️                    │
│                                                   │
│  发现的问题                                       │
│  ┌──────────────────────────────────────────┐   │
│  │ 🔴 AI痕迹：发现 5 处高风险写作模式        │   │
│  │    · "首先...其次...最后" 三段式结构      │   │
│  │    · "蓬勃发展" 等 AI 高频词 ×3          │   │
│  │    → [一键去AI味]                        │   │
│  └──────────────────────────────────────────┘   │

└─────────────────────────────────────────────────┘
```

**关键改进：**
1. 每个问题都有「跳转到对应功能」的行动按钮
2. 原文中问题词汇高亮（用 `issues[].text` 匹配）
3. 检测速度从 15-30s 降到 3-5s（规则引擎承担主要工作）

## 四、UI 设计规范

### 颜色语义
- 90-100：`#10B981` 绿色，「优秀」
- 75-89：`#3B82F6` 蓝色，「良好」
- 60-74：`#F59E0B` 橙色，「需改进」
- 0-59：`#EF4444` 红色，「有问题」

### 问题高亮
- 高风险词：红色背景 `bg-red-500/20` + 红色下划线
- 中风险词：橙色背景 `bg-orange-500/15` + 橙色虚线下划线
- 低风险词：黄色背景 `bg-yellow-500/10` + 黄色点状下划线

### 行动按钮
检测结果的每个问题旁边，都应该有一个跳转到解决方案的快捷按钮：
- AI 痕迹问题 → 「去AI味」按钮
- 原创度低 → 「重新生成」按钮
- 违禁词 → 「高亮显示，手动修改」
