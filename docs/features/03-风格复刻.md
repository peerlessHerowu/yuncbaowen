# 风格复刻（Style）· 功能打磨设计文档

---

## 一、现状分析

### 1.1 当前实现

1. 用户输入 1-10 个文章 URL
2. 后端抓取所有 URL 的正文内容（已实现 fetcher）
3. 把正文 + 分析要求发给 AI
4. AI 返回：`name`（风格名）、`description`（一句话描述）、`prompt_content`（详细提示词）
5. 保存到 `style_prompts` 表
6. 在「定向生成」时可以选择已保存的风格

### 1.2 问题清单

**P0 — 核心功能**
1. 风格提取只靠 AI 分析，没有定量指标支撑（用户不知道风格是否真的被学到了）
2. 没有「风格验证」：保存了风格但不知道用这个风格生成的文章像不像
3. URL 抓取失败时，用户不知道哪个 URL 失败了，也不知道是否影响结果
4. 最多支持 10 个 URL，但没有解释为什么是 10 个

**P1 — 体验**
1. 保存的风格列表只有名称和描述，无法预览 `prompt_content`
2. 没有风格「效果预览」（给一个样本文字，看用这个风格怎么写）
3. 不能编辑已保存的风格（保存后即固定）
4. 没有风格删除确认

**P2 — 质量**
1. AI 分析维度写死在 prompt 里（只有 5 个维度），不够全面
2. 没有针对不同平台的风格提取（公众号风格 vs 小红书风格不一样）
3. 单篇文章风格和多篇文章风格提取的 prompt 没有区分

## 二、优化方案

### 2.1 风格量化指标

在 AI 分析之外，额外用规则引擎计算定量指标：

```typescript
interface StyleMetrics {
  avgSentenceLength: number    // 平均句长（字数）
  paragraphCount: number       // 段落数
  avgParagraphLength: number   // 平均段落长度
  questionRatio: number        // 问句比例
  exclamationRatio: number     // 感叹句比例
  emojiDensity: number         // emoji 密度（个/千字）
  firstPersonRatio: number     // 第一人称比例
  dialogRatio: number          // 对话/引用比例
  listRatio: number            // 列表段落比例
  readingTimeMin: number       // 预估阅读时间（分钟）
}
```

这些指标：
- 用户一眼就能理解（比「语言风格：口语化」更有说服力）
- 在「定向生成」时作为约束条件（生成的文章要匹配这些指标）

### 2.2 风格验证（快速对比）

保存风格后，提供「验证风格」功能：
1. 用这个风格生成一段 200-300 字的样本文章
2. 展示样本文章 + 原始文章的对比
3. 计算风格相似度（基于 `StyleMetrics` 对比）

### 2.3 风格卡片重设计

**现在：**
```
名称：XXX风格
描述：口语化技术导向的...
[选择]  [删除]
```

**优化后：**
```
┌─────────────────────────────────────────────────┐
│  🎨 XXX博主风格                    [编辑] [删除] │
│  口语化技术导向，高信息密度                       │
│                                                   │
│  风格特征                                         │
│  句长 ████░░ 短  |  问句 ██░░░ 少               │
│  段落 ████░░ 多  |  emoji ░░░░░ 无               │
│                                                   │
│  来源：3篇文章 · 2小时前分析                      │
│                                                   │
│  [以此风格生成]  [预览效果]                       │
└─────────────────────────────────────────────────┘
```

### 2.4 URL 输入体验优化

**现在：** 多行文本框，用户要手动一行一行粘贴

**优化：**
- 支持批量粘贴（多个 URL 一次性粘贴，自动拆分）
- 每个 URL 独立显示为 Tag，可以单独删除
- 实时验证 URL 格式
- 抓取前预检（HEAD 请求检查可访问性）
- 抓取结果实时显示（哪个成功、哪个失败、内容长度）

## 四、UI 设计规范

### 风格指标可视化
每个指标用 5 格进度条表示（极短/短/中/长/极长）：
```
句长  ●●●○○  中等
段落  ●○○○○  少
emoji ●●●●○  较多
```

### URL Tag
- 待检测：灰色背景
- 检测中：蓝色 + 旋转 icon
- 成功：绿色 + 字数
- 失败：红色 + 错误原因
