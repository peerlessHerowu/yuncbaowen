## 一、当前实现：原理与结构性局限

### 1.1 当前 pipeline 结构

```
输入文章
   │
   ▼
[1] detectContent  ← 用 AI 打分（0-100），找出扣分句子
   │
   ├── score >= 80 → 直接返回 ✓
   │
   └── score < 80 → [2] rewrite  ← 用 AI 改写，定向修扣分点
                       │
                       └── 循环回 [1]，最多 3 轮
```

核心代码逻辑（`tasks.ts`）：

1. **detectContent** — 把文章发给 Claude，要求返回四维 JSON 评分（AI痕迹 / 违禁词 / 原创度 / 可读性），每个维度定位扣分句子
2. **deaiProcess** — 循环调用 detectContent；如果 AI 痕迹评分 < 80，把扣分点喂回 Claude 让它改写；最多 3 轮

### 1.2 结构性局限

**局限一：自己考试自己批卷**

检测和改写用的是同一个 AI（Claude）。Claude 对"AI味"的理解和 GPTZero、Originality.ai 等专业检测工具完全不同。我们的 `score=58` 不等于真实检测工具里的 58 分，两者没有校准关系。

**局限二：改写在绕圈**

让 Claude 改写 Claude 生成的内容，相当于让同一个人换一种方式说同一件事。句式模式、词汇偏好、逻辑组织方式都来自同一个概率分布。即使表面文字变了，统计特征（困惑度、突发性）没有实质改变。

**局限三：扣分点定位不精确**

`issues` 数组里的 `start/end` 是字符位置，但 Claude 经常数错偏移，导致前端高亮定位出现偏差。

**局限四：改写指令太模糊**

当前 prompt 只说"更口语化、增加个人视角"，没有告诉模型要修的是哪些具体语言模式（em dash 过度、规则三、-ing 虚假深度句式等），所以改写方向不确定，效果依赖运气。

## 二、真正有效的去AI味方法

### 2.1 AI 检测工具检测的是什么

要对抗检测，首先要理解检测工具实际检测的指标。学术界和工业界公认的主要特征有三类：

#### 困惑度（Perplexity）

语言模型对每个词的预测概率的负对数均值。AI 生成的文本倾向于选择最高概率的词，因此困惑度偏低、整体"太顺"。人类写作更随机，会选择不那么显而易见的表达，困惑度更高。

**干预方向**：故意插入低概率词、非标准表达、个人化语言习惯。

#### 突发性（Burstiness）

句子长度变化的方差。人类写作句子长度参差不齐，一会儿长句一会儿短句；AI 写作句子长度均匀，变化幅度小。

**干预方向**：打乱句子长度规律，主动引入极短句（3-5字）和极长句（30字+）交替出现。

#### 统计水印（Watermark）

部分 AI 服务商（如 OpenAI）在 token 采样时植入统计水印，通过特定的 token 选择偏好留下可追踪的痕迹。这类水印理论上可以通过回译（back-translation）或同义词替换打破。

---

### 2.2 三类有效干预方法

#### 方法一：特征对抗（Adversarial Paraphrasing）

针对上述三个可测量特征，定向改写：

- 故意用不寻常的词、不完整的句子、口语化的语气词
- 用短句打断长段落的均匀节奏
- 增加具体细节：真实数字、特定场景、个人叙述

这类方法最直接，但需要对每种语言特征有明确的操作规则，不能靠模糊指令。

#### 方法二：人工干预节点（Human-in-the-loop）

这是目前**可靠性最高**的方法。

流程：AI 生成草稿 → 人工修改 10-20% 的内容（改词、加细节、调结构）→ AI 润色语气

只要有真实的人类改动痕迹，困惑度就会上升，检测通过率显著提高。即使改动量不大，对统计特征的扰动也足够有效。

#### 方法三：多模型混写（Multi-model Blending）

用不同温度参数（temperature）或不同模型生成多个段落版本，然后在段落级别混合拼接。

原理：每个模型有不同的词汇偏好和句式分布，混合后打破单一分布特征，使检测工具难以匹配到某一个模型的指纹。

实践中可以：
- 同一段内容用 temperature=0.3 和 temperature=1.2 各生成一次，选取不同部分
- 用 Claude 生成正文，用 DeepSeek 改写扣分句子

---

### 2.3 为什么"用 AI 改写 AI"效果有限

本质原因：改写前后的内容仍然来自同一个（或相似的）概率分布。

GPT 家族模型共享相似的预训练数据和 RLHF 偏好，即使模型不同，高频词汇（vibrant、crucial、tapestry）和句式模板（"It serves as..."、"Not only...but also..."）会在所有模型上高概率出现。

只有引入**真实人类语言的不规则性**（错别字除外），才能让统计特征真正发生变化。规则引擎 + 定向改写就是模拟这个过程的工程化方案。

## 三、Humanizer Skill：33种AI写作模式

> 来源：[blader/humanizer SKILL.md](https://github.com/blader/humanizer)，基于 Wikipedia 维护的"Signs of AI writing"页面。
>
> 核心洞察（引自 Wikipedia）："LLMs 用统计算法猜测下一个词，结果倾向于适用最广泛场景的最高概率表达。"

这 33 种模式分为五大类，每类都有可操作的 Before/After 对照。

---

### 分类一：内容层面的 AI 套路（Content Patterns）

#### 模式1：过度强调意义、遗产和宏观趋势

**高频词**：stands/serves as、is a testament/reminder、vital/significant/crucial/pivotal、underscores/highlights、reflects broader、symbolizing its ongoing、contributing to、setting the stage for、key turning point、evolving landscape

**问题**：AI 习惯把普通事实升华成"对某一宏观趋势的体现"，加一句重要性声明。

```
❌ The institute was established in 1989, marking a pivotal moment in the evolution of regional statistics.
✅ The institute was established in 1989, part of a wider decentralization of administrative functions.
```

#### 模式2：过度强调知名度和媒体曝光

**高频词**：independent coverage、local/national media outlets、active social media presence

**问题**：AI 堆砌引用来源列表，没有具体内容，只是在声明"很有名"。

```
❌ Her views have been cited in The New York Times, BBC, Financial Times, and The Hindu.
✅ Her views have been cited in The New York Times and the BBC.
```

#### 模式3：以 -ing 结尾的虚假深度句

**高频词**：highlighting/underscoring/emphasizing、reflecting/symbolizing、contributing to、cultivating/fostering、showcasing

**问题**：AI 在句子结尾拼接 -ing 分词短语，制造"深度分析"的假象，实际只是重复前文。

```
❌ The color palette resonates with the region's natural beauty, symbolizing Texas bluebonnets, reflecting the community's deep connection to the land.
✅ The temple is painted blue, green, and gold, colors meant to evoke Texas bluebonnets.
```

#### 模式4：广告式、宣传式语言

**高频词**：boasts a、vibrant、rich（比喻义）、profound、enhancing its、showcasing、exemplifies、commitment to、nestled、in the heart of、groundbreaking、renowned、breathtaking、must-visit、stunning

**问题**：AI 对文化/地理/人物话题极难保持中性语气，习惯堆砌溢美词。

```
❌ Nestled within the breathtaking region of Gonder, Alamata stands as a vibrant town with rich cultural heritage.
✅ Alamata is a town in the Gonder region of Ethiopia.
```

#### 模式5：模糊归因和"weasel words"

**高频词**：Industry reports、Observers have cited、Experts argue、Some critics argue

**问题**：AI 把观点归因给不具名的权威，没有具体来源。

```
❌ Experts believe it plays a crucial role in the regional ecosystem.
✅ Researchers study the Haolai River for its unusual characteristics.
```

#### 模式6："挑战与展望"固定板块

**高频词**：Despite its... faces several challenges、Despite these challenges、Future Outlook

**问题**：AI 生成的文章几乎必有一个公式化的"挑战"段落，格式固定，内容模板化。

```
❌ Despite its industrial prosperity, Korattur faces challenges typical of urban areas... Despite these challenges, Korattur continues to thrive.
✅ Korattur has recurring traffic congestion and water shortages.
```

### 分类二：语言与语法层面（Language & Grammar Patterns）

#### 模式7：AI 高频词汇（最重要的一类）

以下词汇在 2023 年后 AI 生成文本中出现频率远高于人类写作，且常常聚集出现：

```
actually / additionally / align with / crucial / delve
emphasizing / enduring / enhance / fostering / garner
highlight（动词）/ interplay / intricate/intricacies
key（形容词）/ landscape（抽象名词）/ pivotal / showcase
tapestry（抽象名词）/ testament / underscore（动词）
valuable / vibrant
```

**规则**：这些词单独出现问题不大，但一篇文章里出现 3 个以上就是强信号。替换为更具体、更普通的表达。

```
❌ An enduring testament to Italian colonial influence is the widespread adoption of pasta in the local culinary landscape, showcasing how these dishes have integrated.
✅ Pasta dishes, introduced during Italian colonization, remain common, especially in the south.
```

#### 模式8：回避"is/are"（系动词回避）

**高频词**：serves as / stands as / marks / represents + [a]，boasts / features / offers

**问题**：AI 用复杂结构代替简单的 is/are，制造正式感。

```
❌ Gallery 825 serves as LAAA's exhibition space. The gallery boasts over 3,000 square feet.
✅ Gallery 825 is LAAA's exhibition space. The gallery has 3,000 square feet.
```

#### 模式9：否定排比和尾部否定

**问题**："Not only...but also..."或"It's not just about...it's..."被过度使用；还有句末跟一个截断的否定片段（"no guessing"），没有写成完整从句。

```
❌ It's not just about the beat riding under the vocals; it's part of the aggression.
✅ The heavy beat adds to the aggressive tone.

❌ The options come from the selected item, no guessing.
✅ The options come from the selected item without forcing the user to guess.
```

#### 模式10：规则三（Rule of Three）泛滥

**问题**：AI 强行把想法凑成三个一组，制造"全面感"。

```
❌ The event features keynote sessions, panel discussions, and networking opportunities.
✅ The event includes talks and panels. There's also time for informal networking.
```

#### 模式11：优雅变体（同义词循环）

**问题**：AI 的重复惩罚机制导致它不断用同义词替换同一个概念，制造虚假多样性。

```
❌ The protagonist faces challenges. The main character must overcome obstacles. The central figure eventually triumphs. The hero returns home.
✅ The protagonist faces many challenges but eventually triumphs and returns home.
```

#### 模式12：虚假范围（"from X to Y"）

**问题**：AI 用"从 X 到 Y"结构，但 X 和 Y 并不在同一个有意义的量尺上。

```
❌ Our journey has taken us from the Big Bang to the cosmic web, from star birth to dark matter.
✅ The book covers the Big Bang, star formation, and current theories about dark matter.
```

#### 模式13：被动语态和无主语片段

**问题**：AI 经常省略主语或用被动语态隐藏行为主体。

```
❌ No configuration file needed. The results are preserved automatically.
✅ You do not need a configuration file. The system preserves the results automatically.
```

### 分类三：风格层面（Style Patterns）

#### 模式14：Em Dash 过度使用（最可靠的 AI 信号之一）

**规则**：最终改写中不能出现 em dash（—）或 en dash（–），包括前后有空格的版本（` — `）和双连字符（` -- `）。这是硬约束，不是"少用"。

替换优先级：句号（拆成两句）> 逗号（紧凑插入语）> 冒号（引出解释）> 括号（真正的旁白）> 重组句子

```
❌ The term is primarily promoted by Dutch institutions—not by the people themselves.
✅ The term is primarily promoted by Dutch institutions, not by the people themselves.

❌ The new policy — announced without warning — affects thousands of workers.
✅ The new policy, announced without warning, affects thousands of workers.
```

#### 模式15：滥用粗体

**问题**：AI 机械地把短语加粗强调，没有真正的强调意图。

```
❌ It blends **OKRs**, **KPIs**, and visual tools such as the **Business Model Canvas**.
✅ It blends OKRs, KPIs, and visual tools like the Business Model Canvas.
```

#### 模式16：行内标题列表（Bold Header + 冒号）

**问题**：AI 把列表每项做成"**标题：** 正文"格式，是典型的模板输出痕迹。

```
❌
- **User Experience:** The user experience has been significantly improved.
- **Performance:** Performance has been enhanced through optimized algorithms.

✅ The update improves the interface, speeds up load times, and adds encryption.
```

#### 模式17：标题全大写（Title Case）

**问题**：AI 把标题里所有主要单词首字母大写。

```
❌ ## Strategic Negotiations And Global Partnerships
✅ ## Strategic negotiations and global partnerships
```

#### 模式18：Emoji 装饰

**问题**：AI 在标题或列点前加 emoji 装饰，特别是 🚀💡✅ 组合。

```
❌ 🚀 **Launch Phase:** The product launches in Q3
✅ The product launches in Q3.
```

#### 模式19：弯引号

**问题**：ChatGPT 使用弯引号（"..."）而非直引号（"..."）。在中文场景中对应「」和""混用的情况。

### 分类四：沟通模式（Communication Patterns）

#### 模式20：对话协作痕迹（Collaborative Communication Artifacts）

**高频词**：I hope this helps、Of course!、Certainly!、You're absolutely right!、Would you like...、Want me to...?、let me know、here is a...

**问题**：聊天机器人的对话礼貌用语被直接粘贴进内容里，暴露内容的 AI 来源。

```
❌ Here is an overview of the French Revolution. I hope this helps! Let me know if you'd like me to expand.
✅ The French Revolution began in 1789 when financial crisis and food shortages led to widespread unrest.
```

#### 模式21：知识截止声明与推测性填充

**高频词**：as of [date]、Up to my last training update、While specific details are limited、based on available information、maintains a low profile、keeps personal details private、likely [grew up/studied/began]

**问题**：两种相关痕迹。一是留下"我的知识截止到某日期"的硬声明；二是找不到来源时，用一整段"关于找不到资料"的话来掩盖，然后用套话填补空白（"保持低调"、"可能在中产家庭长大"）。

```
❌ While specific details about the founding are not extensively documented, it appears to have been established in the 1990s.
✅ The company's founding date is not documented in the available sources.

❌ Information about her early life is not publicly available, suggesting she maintains a low profile. She likely grew up in a middle-class household.
✅ Her early life is not documented in the available sources.
```

#### 模式22：讨好/谄媚语气

**问题**：过度正面、一味迎合。

```
❌ Great question! You're absolutely right that this is complex. That's an excellent point.
✅ The economic factors you mentioned are relevant here.
```

### 分类五：填充与套话（Filler & Hedging）

#### 模式23：填充短语

常见替换对照：

| 原文 | 改写 |
|------|------|
| In order to achieve this goal | To achieve this |
| Due to the fact that it was raining | Because it was raining |
| At this point in time | Now |
| In the event that you need help | If you need help |
| The system has the ability to process | The system can process |
| It is important to note that the data shows | The data shows |

#### 模式24：过度对冲

**问题**：用多个不确定词堆叠，把一个普通观点变得极度模糊。

```
❌ It could potentially possibly be argued that the policy might have some effect.
✅ The policy may affect outcomes.
```

#### 模式25：通用正面结尾

**问题**：文章末尾加一段"未来充满希望"的模板式收尾，没有任何具体内容。

```
❌ The future looks bright. Exciting times lie ahead as they continue toward excellence.
✅ （直接以最后一个具体事实结束，删掉这段）
```

#### 模式26：连字符词对滥用

**高频词**：third-party、cross-functional、data-driven、decision-making、high-quality、real-time、long-term、end-to-end

**规则**：作定语时保留连字符（a high-quality report），作表语时去掉（the report is high quality）。AI 不管位置一律加连字符。

```
❌ The team is cross-functional, the report is high-quality, the methodology is data-driven.
✅ The team is cross functional, the report is high quality, the methodology is data driven.
```

#### 模式27：权威感套语

**高频词**：The real question is、at its core、in reality、what really matters、fundamentally、the heart of the matter

**问题**：AI 用这类短语假装在揭示更深层的真相，但后面的句子通常只是在重复一个普通观点。

```
❌ The real question is whether teams can adapt. At its core, what really matters is organizational readiness.
✅ The question is whether teams can adapt. That depends mostly on whether the organization is ready to change.
```

#### 模式28：预告式开场白

**高频词**：Let's dive in、let's explore、Here's what you need to know、without further ado

**问题**：AI 喜欢在正文开始前宣布"我接下来要做什么"，而不是直接做。

```
❌ Let's dive into how caching works in Next.js. Here's what you need to know.
✅ Next.js caches data at multiple layers, including request memoization and the router cache.
```

#### 模式29：碎片式标题（Fragmented Headers）

**问题**：一个标题后面跟着一个单句废话，然后才是真正内容。

```
❌ ## Performance
Speed matters.
When users hit a slow page, they leave.

✅ ## Performance
When users hit a slow page, they leave.
```

#### 模式30：变更视角写作（Diff-Anchored Writing）

**问题**：文档写成在叙述"这次改动了什么"，而不是描述"事物现在是什么样的"。

```
❌ This function was added to replace the previous O(n²) approach.
✅ This function uses a hash map for O(1) lookups.
```

#### 模式31：制造感的短句戏剧性堆叠

**问题**：连续多个极短陈述句，制造戏剧性节奏，但实际上每句都在夸大普通信息。

```
❌ Then AlphaEvolve arrived. It had no preference for symmetry. No aesthetic prior. No nostalgia for human taste. The old rules were gone.
✅ AlphaEvolve changed the search because it did not favor symmetry or human-looking designs.
```

#### 模式32：格言公式

**高频结构**：X is the Y of Z、X becomes a trap、X is not a tool but a mirror

**问题**：AI 把普通观点包装成听起来深刻的格言，但去掉格言外壳后内容平淡。

```
❌ Symmetry is the language of trust. Efficiency becomes a trap when teams forget the human layer.
✅ Symmetric layouts feel more predictable to users. Teams can over-optimize workflows.
```

#### 模式33：假装坦诚的开场钩子

**高频词**：Honestly?、Look、Here's the thing、The thing is、Let's be honest、Real talk

**问题**：用一句"假坦诚"的停顿制造亲密感，然后说出一个普通观点。真正坦诚的人会直接说出来。

```
❌ Is it worth the price? Honestly? It depends on how often you'll use it.
✅ Whether it's worth the price depends on how often you'll use it.
```

### 3.1 哪些特征不能作为 AI 判断依据（误报警示）

以下特征**单独出现**时不是 AI 信号，不要误改：

- **语法完美、风格一致** — 专业作者或经过编辑的稿子同样如此
- **正式/学术词汇** — AI 滥用的是特定词（见模式7），不是所有高级词
- **单个 em dash** — 很多记者和编辑习惯用，要看是否和其他模式聚集出现
- **单个"Honestly"或"look"** — 在对话体写作里很正常，问题是把它作为独立钩子开场
- **被动语态** — 科学/法律写作本来就大量用，不等于 AI
- **一个短强调句** — 人类也用短句收尾；问题是连续多个堆叠

**判断 AI 写作要看模式簇，不是单一特征**。一篇文章同时出现 em dash + vibrant + rule-of-three + "Conclusion"段落，才是强信号。

### 3.2 人类写作的保留信号（遇到这些要手下留情）

- **具体的、难以伪造的细节**：真实地址、奇怪的引用、"楼上牙医诊所旁边的律师"——AI 会模糊细节，人类会囤积细节
- **混合感情和未解决的张力**："我觉得这大体上是好的，但有什么地方让我不安，我说不清楚"
- **句子长度有真实变化**：真实写作在极短和极长句之间跳跃，AI 趋向中等均匀
- **真正的旁白和自我纠正**："（我一直想写'几乎'，但那次真的是肯定的。）"

---

## 四、两个方向的结合方案

### 4.1 为什么要结合，而不是选一个

**方向 A（规则引擎检测）** 的优势：快、确定性强、不消耗 token、每个命中点可精确定位。
缺点：只能识别模式，不能改写。

**方向 B（Skill 注入 system prompt）** 的优势：AI 理解语义，能在改写时保留原意、调整语气。
缺点：没有精确的问题定位，靠 AI 自己判断改什么，方向不稳定。

**两者结合的核心思路**：

```
规则引擎 → 精确诊断（我知道哪里有问题、有几个问题、是哪类问题）
AI 改写  → 精确治疗（带着诊断结果去改，而不是盲改）
```

类比医学：不是"你感觉哪里不舒服，自己治一下"，而是"先做检查，确认病因，然后对症下药"。

### 4.2 结合后的新 Pipeline

```
输入文章
    │
    ▼
┌─────────────────────────────────────┐
│  Step 1: 规则引擎检测（本地，零 token）  │
│                                     │
│  扫描 33 种 AI 模式，输出：           │
│  - 命中的模式列表（模式7/14/28...）   │
│  - 每处命中的文字位置和原因           │
│  - 规则引擎评分（0-100）              │
└─────────────────────────────────────┘
    │
    ├── 命中数 = 0 → 评分 ≥ 90 → 直接返回（不消耗 AI token）
    │
    ▼
┌─────────────────────────────────────┐
│  Step 2: AI 定向改写                 │
│                                     │
│  System prompt = humanizer Skill    │
│  核心指令（33种模式的精华版）          │
│                                     │
│  User prompt = 原文 +                │
│    "规则引擎检测到以下问题：          │
│     [模式列表+具体命中词句]           │
│     请重点修复这些问题"               │
└─────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────┐
│  Step 3: 规则引擎复检（本地，零 token） │
│                                     │
│  对改写结果再次扫描，确认：           │
│  - 命中数是否减少                    │
│  - 新评分是否提升                    │
└─────────────────────────────────────┘
    │
    ├── 新评分 ≥ 80 → 返回结果
    │
    └── 新评分 < 80 且未达最大轮次 → 回到 Step 2
```

### 4.3 关键设计决策

#### 决策一：检测和改写分工明确

| 职责 | 执行者 | 理由 |
|------|--------|------|
| 模式识别 / 定位 / 评分 | 规则引擎 | 快、准、可解释、零 token |
| 语义保留的改写 | AI（Claude） | 只有 AI 能在改句子的同时保住原意 |
| 改写质量验收 | 规则引擎 | 客观、一致、不受 AI 自我评分偏差影响 |

#### 决策二：规则引擎只扫高确定性模式

33 种模式中，有几类确定性极高，适合用正则/词表检测：

- **模式7（AI 高频词）**：维护一个词表，文章中命中超过 N 个即扣分
- **模式14（Em dash）**：正则 `—` 或 `–` 出现次数
- **模式10（规则三）**：检测 `A、B 和 C` / `A, B, and C` 的三元枚举密度
- **模式3（-ing 结尾虚假深度）**：检测句末 `，/。` 前的 `-ing` 分词短语
- **模式28（预告式开场白）**：词表匹配（Let's dive in / Here's what you need to know）

另一些模式（如模式22讨好语气、模式32格言公式）语义性更强，交给 AI system prompt 处理，不用规则检测。

#### 决策三：system prompt 使用 Skill 核心精华，不全量注入

原 humanizer Skill 约 29000 字节，全量注入会大量消耗 context window。

提炼核心原则（约 2000 字），覆盖最高命中率的 15 个模式，其余靠规则引擎定位后在 user prompt 里点名指出。
