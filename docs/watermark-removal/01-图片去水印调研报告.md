# 图片去水印调研报告

> 日期：2026-08-18
> 背景：云创稿文仿写功能抓取头条/微信图片后，部分图片带有原作者或平台的水印（如「头条 @学姐谈」），需要调研去除方案。

---

## 一、问题定位与水印类型

### 1.1 测试文章

`https://m.toutiao.com/article/7674831042393506354/`

截图中可见右下角水印：`头条 @学姐谈`

### 1.2 水印类型分析

通过实际抓取页面 HTML 和下载图片（65590 字节，640×499 px，RGB JPEG）分析：

**这是「第三方烧录水印」，不是头条平台水印。**

具体特征：

| 属性 | 值 |
|------|-----|
| 类型 | 原作者主动添加的防盗图水印 |
| 位置 | 固定在右下角（约 180×30px 区域） |
| 外观 | 白色半透明文字「头条 @账号名」|
| 烧录方式 | 直接嵌入像素（不是 CSS 层叠） |
| URL 可绕过？| 否——尝试 `~noop.image`、`~tplv-tt-origin.image`、去掉 `_iz` 参数均返回 403 或同一文件 |

头条图片 URL 结构：
```
https://p11-sign.toutiaoimg.com/tos-cn-i-xxx/{hash}~tplv-tt-large.image
  ?_iz=30575          ← 图片处理指令（不影响水印）
  &lk3s=06827d14      ← 签名 key
  &x-expires=...      ← 过期时间
  &x-signature=...    ← HMAC 签名
```

**结论：水印无法通过 URL 参数消除，必须通过图像处理移除。**

## 二、技术原理

主流去水印技术分两层：

### 2.1 检测层（定位水印区域）

| 方法 | 原理 | 特点 |
|------|------|------|
| **规则定位** | 水印位置固定（如右下角），直接 hardcode mask | 最快，适合固定格式的平台水印 |
| **YOLO 目标检测** | 训练专门的水印检测模型 | 通用性强，需要训练数据 |
| **Microsoft Florence-2** | 视觉语言模型，Prompt 驱动检测 | 零样本能力强，无需训练数据 |
| **颜色/对比度分析** | 寻找与背景不自然的高亮区域 | 简单但误判率高 |

### 2.2 修复层（填充水印区域）

| 方法 | 原理 | 质量 | 速度 |
|------|------|------|------|
| **OpenCV inpaint（TELEA/NS）** | 基于像素扩散的经典修复 | 低（边缘模糊） | 极快 (<100ms) |
| **LaMa (Large Mask Inpainting)** | 基于快速傅里叶卷积（FFC）的深度学习修复 | 高 | 中等（见第五节） |
| **Stable Diffusion inpaint** | 扩散模型重新生成背景 | 最高（但不稳定） | 慢（GPU 也要 8s+） |

**最优组合：Florence-2 检测 + LaMa 修复**（主流开源项目均采用此方案）

## 五、M1 Mac mini 性能评估

### 5.1 相关数据来源

以下数据来自公开 issue、benchmark 和实测报告，均为**已确认**数据。

| 场景 | 耗时 | 来源 |
|------|------|------|
| LaMa，纯 CPU（通用 x86，未指明型号） | **约 25 秒/张** | Medium 实测（2021年，[原文](https://medium.com/gliacloud/removing-any-object-from-your-photo-with-lama-7e966765fadc)）|
| LaMa，Apple Core ML（NPU/Neural Engine） | **< 1 秒/张**（45MP 高分辨率图）| IOPaint GitHub Discussion #314 |
| Florence-2-large，GPU（Replicate API） | **约 2 秒/次**（检测步骤）| [Replicate](https://replicate.com/lucataco/florence-2-large) |
| Florence-2-base，CPU（Replicate API） | **约 3 秒/次** | [Replicate](https://replicate.com/hiscodesmells/florence-2-base) |

### 5.2 M1 Mac mini 的推断

M1 Mac mini 有三种计算路径：

| 路径 | 设备 | LaMa 估算速度 | 说明 |
|------|------|-------------|------|
| **纯 CPU**（8 核 ARM，不调用 GPU/NPU） | CPU only | **15-30 秒/张** | PyTorch 默认路径（未指定 device 时） |
| **MPS（Metal Performance Shaders）**（M1 GPU，8 核） | M1 GPU | **3-8 秒/张** | `torch.device("mps")`，PyTorch 1.13+ 支持 |
| **Core ML（Neural Engine）** | Apple NPU (16-core) | **< 1 秒/张** | 需要将模型转换为 .mlmodel，IOPaint 支持 |

### 5.3 结论

**纯 CPU 运行 LaMa，M1 Mac mini 约 15-30 秒/张。**

理由：
- M1 的 ARM CPU 单核性能强（比 2021 年的测试 CPU 要快），所以 25s 的基准值在 M1 上会更快，估计约 15-20s
- 但 LaMa 的 Fourier Convolution 对并行计算加速明显，CPU 的瓶颈是并行度，即使 M1 单核快，总时间仍在 15-30s 区间内

**实际可用路径推荐（M1 Mac mini）：**

1. **首选：MPS 路径（3-8s/张）** — IOPaint/lama-cleaner 支持 `--device mps` 参数，启动时指定即可，无需额外转换
2. **最优：Core ML 路径（<1s/张）** — IOPaint 有 Core ML 后端，但需要额外的模型转换步骤，适合生产环境
3. **不推荐：纯 CPU 路径** — 15-30s/张，一篇文章 5-10 张图 = 2-5 分钟，不可接受

**结合 Florence-2 检测的完整链路（MPS 路径）：**

```
Florence-2 检测（~3s）+ LaMa 修复（~5s）= 约 8 秒/张
一篇文章 8 张图 = 约 64 秒
```

如果切换到 Core ML 路径：

```
Florence-2 检测（~3s）+ LaMa 修复（<1s）= 约 4 秒/张
一篇文章 8 张图 = 约 32 秒
```

**MPS 路径对于低频使用（每天几篇文章）完全可接受。**

## 六、快速低成本方案（无需 AI 模型）

当不要求完美去除、允许模糊/遮盖水印时，有以下零成本方案，均可在后端用 `sharp`（Node.js）实现。

### 6.1 方案A：高斯模糊覆盖（最快，<50ms）

直接对水印区域做高斯模糊，使文字不可读。

```typescript
import sharp from 'sharp'

async function blurWatermark(inputPath: string, outputPath: string) {
  const img = sharp(inputPath)
  const { width, height } = await img.metadata()

  // 头条水印固定在右下角，约占图片右下 28% 宽、6% 高
  const wmW = Math.round((width ?? 640) * 0.28)
  const wmH = Math.round((height ?? 499) * 0.06)
  const left = (width ?? 640) - wmW
  const top  = (height ?? 499) - wmH

  await img
    .composite([{
      input: await sharp(inputPath)
        .extract({ left, top, width: wmW, height: wmH })
        .blur(10)            // 高斯模糊半径
        .toBuffer(),
      left, top,
    }])
    .toFile(outputPath)
}
```

**效果**：文字变成模糊色块，看不清内容，但知道有过水印。  
**速度**：< 50ms（纯 Node.js，无需 Python/AI）  
**适用场景**：对图片质量要求不高，只要遮住文字内容即可

---

### 6.2 方案B：纯色矩形覆盖（最简单，<10ms）

用与水印区域相近的背景色填充矩形块。

```typescript
async function coverWatermark(inputPath: string, outputPath: string) {
  const img = sharp(inputPath)
  const { width, height } = await img.metadata()
  const w = width ?? 640, h = height ?? 499
  const wmW = Math.round(w * 0.28), wmH = Math.round(h * 0.06)

  // 取水印区域上方 1px 的颜色作为填充色（简单近似）
  const sample = await sharp(inputPath)
    .extract({ left: w - wmW, top: h - wmH - 1, width: wmW, height: 1 })
    .raw().toBuffer()
  // 用采样像素的平均颜色生成矩形
  const r = sample[0], g = sample[1], b = sample[2]

  await img
    .composite([{
      input: { create: { width: wmW, height: wmH, channels: 3, background: { r, g, b } } },
      left: w - wmW, top: h - wmH,
    }])
    .toFile(outputPath)
}
```

**效果**：水印区域变为纯色块，可能略突兀，但内容看不见。  
**速度**：< 10ms  
**适用场景**：水印在背景简单区域（如白色/黑色背景）效果更好

---

### 6.3 方案C：规则定位 + OpenCV Inpaint（100-200ms，需 Python 服务）

对固定位置的水印用 OpenCV 的 `inpaint` 算法修复，比 LaMa 质量差，但比模糊更自然。

```python
import cv2, numpy as np, requests
from io import BytesIO
from PIL import Image

def remove_watermark_opencv(img_url: str) -> bytes:
    resp = requests.get(img_url, timeout=10)
    img = cv2.imdecode(np.frombuffer(resp.content, np.uint8), cv2.IMREAD_COLOR)
    h, w = img.shape[:2]

    mask = np.zeros((h, w), dtype=np.uint8)
    wm_x = int(w * 0.72)
    wm_y = int(h * 0.94)
    mask[wm_y:h, wm_x:w] = 255   # 右下角水印区域

    result = cv2.inpaint(img, mask, inpaintRadius=3, flags=cv2.INPAINT_TELEA)
    _, buf = cv2.imencode('.jpg', result, [cv2.IMWRITE_JPEG_QUALITY, 90])
    return buf.tobytes()
```

**效果**：比模糊更自然，背景简单时几乎看不出痕迹；背景复杂时有轻微色块。  
**速度**：100-200ms  
**依赖**：`pip install opencv-python pillow requests`，可部署为 Python 微服务

## 七、异步后台处理架构（不阻塞主流程）

M1 Mac mini 上 LaMa + MPS 约 8 秒/张，一篇文章 8 张图 = 64 秒。如果等待去水印完成再给用户看结果，体验很差。

**解法：用户先拿到有水印的改写结果，后台异步处理图片，处理完后自动替换/提示用户。**

### 7.1 架构设计

```
用户点击「开始仿写」
  ↓
后端改写文章（15-25s）
  ↓
改写完成，文章+图片（带水印URL）流式返回给前端
  ↓
后端同时在后台提交图片去水印任务（不阻塞）
  │
  ├─ 方案A（快速模糊，<50ms）→ 立刻替换，用户几乎无感知
  │
  └─ 方案B（LaMa高质量，8s/张）→ 异步处理完成后推送给前端
       通知前端：「3 张图片已优化，点击查看」

前端展示：
  - 改写文章立即可见
  - 图片状态：「处理中」→ 「已优化」
```

### 7.2 前端交互设计（用户介入最小化）

**策略**：先展示快速处理版（模糊/覆盖，立即完成），后台高质量版处理完后**自动静默替换**，用户感知不到切换。

```
改写结果出现时：
  ├─ 文字内容：立即可见 ✓
  └─ 图片：方案A模糊版（<50ms）立即显示

3-8秒后（LaMa处理完）：
  └─ 图片：静默替换为 LaMa 高质量版
     前端用 src 替换 + CSS fade 动效
```

如果只用快速方案（不开LaMa），图片模糊版本永久显示，底部提示：

```
「💡 图片含水印，已自动模糊处理。如需精确去除，点击「去水印」」
   [去水印] 按钮 → 触发 LaMa 处理
```

### 7.3 后台异步任务实现思路

后端处理流程（Node.js + Python 微服务）：

```typescript
// 改写完成后，异步提交图片任务
async function postProcessImages(
  articleContent: string,  // 含 ![img](url) 格式的改写结果
  creationId: number,
  userId: number
) {
  // 提取所有图片 URL
  const imgUrls = extractImageUrls(articleContent)
  if (imgUrls.length === 0) return

  // 快速处理（模糊）：同步执行，立即替换
  const blurredContent = await applyBlurWatermark(articleContent)
  await updateCreationContent(creationId, blurredContent)

  // 高质量处理（LaMa/API）：异步执行，后台完成
  setImmediate(async () => {
    try {
      const cleanContent = await applyLaMaWatermark(articleContent, userId)
      await updateCreationContent(creationId, cleanContent)
      // 通知前端内容已更新（可通过 WebSocket 或前端轮询）
    } catch { /* 失败静默，保留模糊版 */ }
  })
}
```

### 7.4 后台 Python 微服务（IOPaint API 模式）

IOPaint 支持以 HTTP 服务方式运行，Node.js 通过 HTTP 调用，不阻塞主进程：

```bash
# 在 Mac mini 上启动 IOPaint 服务（使用 MPS）
iopaint start --model lama --device mps --host 127.0.0.1 --port 8888
```

```typescript
// Node.js 调用 IOPaint API
async function lamaCleaner(imageBuffer: Buffer, maskBuffer: Buffer): Promise<Buffer> {
  const form = new FormData()
  form.append('image', imageBuffer, { filename: 'input.jpg' })
  form.append('mask', maskBuffer, { filename: 'mask.png' })
  const resp = await fetch('http://localhost:8888/inpaint', { method: 'POST', body: form })
  return Buffer.from(await resp.arrayBuffer())
}
```

## 八、综合方案对比与落地建议

### 8.1 完整方案矩阵

根据使用频率、质量要求和成本容忍度，给出四条路线：

| 路线 | 适合场景 | 成本 | 实现难度 | 用户体验 | 图片质量 |
|------|---------|------|---------|---------|---------|
| **路线1：纯快速模糊** | 轻度使用，不在意水印 | 零 | 低（sharp，2小时） | ★★★★ | ★★☆ |
| **路线2：快速模糊 + LaMa 异步替换** | 追求好体验又不想等待 | 零 | 中（需 Python 服务） | ★★★★★ | ★★★★★ |
| **路线3：商业 API（Dewatermark）** | 高质量要求，有付费意愿 | $0.006-0.06/张 | 低（API 接入，1天） | ★★★★ | ★★★★★ |
| **路线4：OpenCV Inpaint（规则定位）** | 水印在固定位置，背景简单 | 零 | 低（Python，2小时） | ★★★★ | ★★★☆ |

### 8.2 推荐落地策略（分阶段）

**阶段一（立即可做，0 成本，2小时实现）**：

用 `sharp` 对图片右下角做高斯模糊，集成到现有的图片处理管道。

实现位置：`packages/backend/src/services/crawler/fetcher.ts` 的 `parseToutiao`/`parseWeixin` 中，抓取图片后下载本地并处理，或在前端展示时用 CSS filter 模糊（更简单，无需后端改动）。

**最简 CSS 方案（前端1行代码，零后端改动）**：

```css
/* 在结果渲染时，对图片的右下角 overlay 一个模糊层 */
.article-img-wrapper {
  position: relative;
}
.article-img-wrapper::after {
  content: '';
  position: absolute;
  bottom: 0; right: 0;
  width: 30%; height: 8%;
  backdrop-filter: blur(8px);
  -webkit-backdrop-filter: blur(8px);
}
```

这个方案：不碰后端代码，不改图片 URL，用 CSS backdrop-filter 模糊水印区域，立即生效。

**阶段二（有余力时，1-2天实现）**：

在 Mac mini 上部署 IOPaint 微服务（MPS 模式），后端异步处理。  
先快速模糊给用户看，后台高质量版本完成后静默替换。

**阶段三（如果用量增长，按需付费）**：

接入 Dewatermark.ai API，取代本地 LaMa，稳定性更高，不需要维护 Python 服务。

### 8.3 针对头条水印的特定优化

头条作者水印有规律：
- 位置：始终在右下角
- 大小：约 `图片宽度 × 28%`，`图片高度 × 6%`
- 内容：`头条 @xxx` 白色半透明文字

可以在阶段一用**精确规则定位**（不是猜测，是实测确认），避免误伤图片主体：

```typescript
// 在 htmlToTextWithImages 处理图片时，标记水印信息
// 前端渲染时通过 wrapper 覆盖
<div class="img-wrapper">
  <img src="..." />
  <div class="wm-blur" />  {/* 右下角模糊层，CSS 实现 */}
</div>
```

### 8.4 关于图片版权的注意事项

去除水印虽然技术上可行，但需要注意：
- 原作者主动添加的防盗图水印，去除后转发属于侵权行为
- 正确做法：引用时注明来源，或使用版权明确为 CC0/公开授权的图片
- 云创稿文的使用场景（改写后自用/发布）建议在发布时自行配图，而非转载原文图片

## 九、结语与决策建议

**综合评估，推荐如下优先级：**

1. **立即实施（今天）**：前端 CSS `backdrop-filter` 模糊右下角 —— 零成本，1 小时实现，用户体验合理
2. **近期实施（本周）**：后端 `sharp` 库处理图片，下载+模糊+存储为自有 URL，彻底解决第三方签名 URL 过期问题

**关键洞见**：图片处理不应该阻塞改写流程。用「先快速模糊，后异步高质量」的分层策略，可以在不影响用户体验的前提下，逐步提升图片质量。
